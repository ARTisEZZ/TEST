# Telegram-бот: вопросы студента по диалогу с Claude

Студент пишет боту в Telegram вопросы о том, как выполнялось моделирование, а Claude отвечает,
опираясь на ваш диалог с ним в claude.ai (и, если хотите, на дополнительные файлы: код, данные, отчёт).

```
Студент ──► Telegram-бот (bot.py) ──► Claude API
                                       system: инструкции + ваш чат (кэшируется на 1 час)
                                       messages: история вопросов этого студента
```

**Важно:** у бота нет «живого» доступа к чатам claude.ai, потому что API к ним не подключается.
Поэтому нужный чат один раз выгружается в файл, и бот работает с этой копией. Если чат
продолжится, выгрузите его заново и перезапустите бота.

## 1. Выгрузить чат из claude.ai

**Вариант А: экспорт данных (сохраняется всё, включая артефакты с кодом)**

1. claude.ai → **Settings → Privacy → Export data**. На почту придёт ссылка на zip-архив.
2. Найдите нужный чат и сохраните его:

   ```bash
   python export_chat.py data-export.zip --list                   # список чатов
   python export_chat.py data-export.zip --name "моделирование"   # → context/chat.md
   ```

**Вариант Б: вручную.** Скопируйте текст чата в `context/chat.md`. Можно также попросить
Claude в том же чате написать подробный конспект: постановка, допущения, модель, параметры,
код, результаты. Этот конспект тоже сохраните в `context/`.

Всё, что лежит в `context/` (`.md`, `.py`, `.txt`, `.csv` и т. п.), бот читает при старте.
Туда можно добавить исходники модели или описание данных.

## 2. Создать бота и получить ключи

1. В Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` и получите токен.
2. Ключ Claude API создаётся на [platform.claude.com](https://platform.claude.com) → API Keys.
   Это отдельная оплата по токенам, подписка claude.ai сюда не входит.
3. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN` и `ANTHROPIC_API_KEY`.

## 3. Запустить

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

Попросите студента написать боту `/start`. Бот ответит «Доступ закрыт» и покажет его Telegram ID.
Впишите этот ID в `ALLOWED_USER_IDS` в `.env` и перезапустите бота. Остальным пользователям бот
отвечать не будет.

Бот работает через long polling, поэтому публичный адрес и вебхуки не нужны. Чтобы бот работал
круглосуточно, запустите его на любом сервере или VPS (например, через `systemd`, `tmux` или Docker).

## Что умеет

- Отвечает только пользователям из `ALLOWED_USER_IDS` и только в личных сообщениях.
- Помнит последние `MAX_HISTORY_TURNS` вопросов каждого студента. Команда `/reset` очищает историю.
- Пишет все вопросы и ответы в `logs/qa.jsonl`, так что вы видите, что спрашивали.
- Модель: Claude Opus 5.5, глубина рассуждений `BOT_EFFORT` (по умолчанию `medium`; для более
  глубоких разборов поставьте `high`).
- Включены server-side fallbacks: если фильтры безопасности ошибочно отклонят вопрос, API сам
  повторит его на резервной модели.

## Стоимость

Чат передаётся в каждом запросе, но кэшируется (prompt caching, TTL 1 час):

- первый вопрос за час: запись чата в кэш (≈ $0.80 за 100K токенов чата);
- следующие вопросы: чтение из кэша (≈ $0.02 за 100K токенов) плюс сам ответ (обычно несколько центов).

Попадание в кэш видно в `logs/qa.jsonl` по полю `cache_read_input_tokens`.

## Приватность

Студент может попросить бота пересказать или процитировать любую часть материалов из `context/`.
Не кладите туда то, что студенту видеть не нужно: личные сообщения, ключи, чужие данные.
`.env`, `context/` и `logs/` добавлены в `.gitignore`.
